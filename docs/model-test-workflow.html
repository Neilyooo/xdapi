新模型测试流程

把新模型验证改成矩阵流程，先找上游真实可用路径，再决定是否进入 XDAPI 中转接入。

默认顺序

  • 先测 moma.cmecloud.cn，再测 zhenze-huhehaote.cmecloud.cn。
  • 每个上游先测 POST /v1/chat/completions。
  • 只有当 chat 的所有模型名变体都失败后，才扩展到 POST /v1/responses。
  • 上游直连确认成功后，才进入 XDAPI relay / channel / pricing 验证。

模型名变体

  • 每个候选先试裸名，再试 vendor 前缀名。
  • 示例：qwen3.6-plus -> qwen/qwen3.6-plus。
  • 若上游详情页给出更明确的原文名，以原文名为准。

记录字段

  • host、endpoint、model、stream 开关。
  • HTTP 状态码、request id、content-type。
  • 首段响应片段。

XDAPI 接入后验证

  • 复核 live channel 的 base_url、models、group、model_mapping，不能以本地代码或旧记录代替线上配置。
  • 先跑管理员态 channel/test/{channel_id}，确认请求能到正确上游。
  • 再跑操练场同路径 POST /pg/chat/completions，分别测 stream=false 和至少一个 stream=true smoke test。
  • 如果操练场报 SSE Error: openai_error，先检查返回体是否为错误 JSON、渠道 base_url 是否指向临时隧道或旧上游，以及 group 是否仍在用 auto。

早停规则

  • 找到第一个双流式成功组合后立即停止。
  • 已确认成功的等价组合不再重复测试。
  • 只有全部 chat 变体失败后才进入 responses。

当前已验证样例

  • qwen3.6-plus 在 https://moma.cmecloud.cn/v1/chat/completions 上，使用 model=qwen/qwen3.6-plus 时，stream 与 non-stream 都返回 200。
  • qwen3-vl-plus、qwen-mt-plus、qwen3-omni-flash、qwen-mt-flash、qwen3.5-plus、qwen3-max 也已通过同一路径验证。
  • 2026-05-27 11:13 CST 线上 XDAPI 已修复 Moma 渠道 base_url，7 个 Moma 新模型通过操练场 /pg/chat/completions、group=1x、stream=false 验证；qwen3.5-plus 额外通过 stream=true smoke test。
