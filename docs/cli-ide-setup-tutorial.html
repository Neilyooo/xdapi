XD API 小白接入教程

这份教程给第一次使用 AI 编程工具的用户看：先拿到 XD API 令牌，再把 Base URL 和 API Key 填进 Codex、Claude Code、VS Code、Cursor、Cline、Roo Code 或国产 IDE。

Base URL： https://api.xingdingwangluo.cn/v1 普通用户：default 1x 统一分组 更新时间：2026-05-13

目录

1. 先记住三件事 2. 创建 XD API 令牌 3. URL 应该怎么填 4. OpenAI Codex CLI 5. Claude Code 6. VS Code 7. Cursor 8. 国产 IDE / 插件 9. 模型怎么选 10. 测试与排错

1. 先记住三件事

  1. API Key 就是你在 XD API 网站里创建的令牌，不要发到群里，不要截图泄露。
  2. Base URL 通常填 https://api.xingdingwangluo.cn/v1，不要填完整的 /chat/completions。
  3. 普通用户 使用 default 1x 统一分组；2026-05-16 起，已部署 CMCC token 计费模型不再用 vip/agent 做访问门槛。
判断一个软件怎么填：如果它要的是 Base URL，填 https://api.xingdingwangluo.cn/v1；如果它明确要“完整接口地址”，再填 https://api.xingdingwangluo.cn/v1/chat/completions。

2. 创建 XD API 令牌

  1. 打开 https://api.xingdingwangluo.cn 并登录。
  2. 进入控制台的“令牌 / API Keys / Tokens”页面。
  3. 点击“新建令牌”。新手建议先不要限制模型和 IP，确认能跑通后再收紧权限。
  4. 复制生成的 Key。Key 通常只完整显示一次，丢了就重新建一个。
  5. 令牌分组保持默认即可。旧的 vip/agent 只作为历史兼容 key，不再代表模型权限。

3. URL 应该怎么填

用途填写内容什么时候用
OpenAI 兼容 Base URLhttps://api.xingdingwangluo.cn/v1Codex、Cursor、Cline、Roo Code、Continue、大多数国产 IDE
聊天完整接口https://api.xingdingwangluo.cn/v1/chat/completions只有软件明确要求完整 Chat Completions URL 时才填
Responses 接口https://api.xingdingwangluo.cn/v1/responsesCodex 或支持 Responses API 的工具
向量接口https://api.xingdingwangluo.cn/v1/embeddings知识库、检索、RAG 工具
排序接口https://api.xingdingwangluo.cn/v1/rerank支持 rerank 的检索工具
Claude 兼容 Base URLhttps://api.xingdingwangluo.cnClaude Code 这类会自动拼接 /v1/messages 的工具

4. OpenAI Codex CLI 配置

Codex CLI 是终端里的 AI 编程助手。OpenAI 官方文档给出的安装命令是 npm i -g @openai/codex，PackyCode 的文档也采用 ~/.codex/config.toml 加 auth.json 的配置方式。

4.1 安装 Node.js

先安装 Node.js 18 或更高版本。装好后在终端执行：

node -v
npm -v

能看到版本号，就继续下一步。

4.2 安装 Codex

npm i -g @openai/codex
codex --version

4.3 配置 ~/.codex/config.toml

macOS / Linux / WSL 路径是 ~/.codex/config.toml；Windows 路径是 %USERPROFILE%\.codex\config.toml。没有文件就手动创建。

model_provider = "xdapi"
model = "deepseek-v3"
model_reasoning_effort = "medium"
disable_response_storage = true

[model_providers.xdapi]
name = "xdapi"
base_url = "https://api.xingdingwangluo.cn/v1"
wire_api = "responses"
requires_openai_auth = true

4.4 配置 auth.json

同一目录下创建或编辑 auth.json：

{
  "OPENAI_API_KEY": "把你的 XD API 令牌粘贴到这里"
}

4.5 启动测试

cd 你的项目目录
codex

进入 Codex 后输入：请只回复 ok。能返回内容就说明配置成功。

5. Claude Code 配置

Claude Code 官方现在推荐原生安装，也支持 npm 安装。它默认走 Anthropic 协议，因此和 Codex 的 URL 不一样。

5.1 安装

# macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash

# 或者使用 npm
npm install -g @anthropic-ai/claude-code

5.2 用 XD API 令牌启动

XD API 支持 /v1/messages 入口。Claude Code 会自己拼接路径，所以这里的 Base URL 不要带 /v1。

export ANTHROPIC_BASE_URL="https://api.xingdingwangluo.cn"
export ANTHROPIC_API_KEY="把你的 XD API 令牌粘贴到这里"
claude
如果你的 Claude Code 版本或模型选择强依赖 Anthropic 官方模型名，可能会出现模型列表或 404 问题。新手优先用 Codex、Cline、Roo Code、Cursor 这类 OpenAI 兼容工具，排错成本更低。

6. VS Code 配置

6.1 Codex 插件

  1. 在 VS Code 扩展市场搜索并安装 OpenAI Codex 相关插件。
  2. 新版插件通常读取 ~/.codex/config.toml 和 auth.json，所以先按上面的 Codex CLI 配好。
  3. 重启 VS Code，然后打开项目目录，在 Codex 面板里测试一句“只回复 ok”。

6.2 Cline / Roo Code / Continue

这类插件一般都有“OpenAI-compatible / 自定义 OpenAI 兼容接口”选项，按下面填：

字段填写
API ProviderOpenAI Compatible 或 OpenAI-compatible
Base URLhttps://api.xingdingwangluo.cn/v1
API Key你的 XD API 令牌
Modeldeepseek-v3、qwen2.5-7b-instruct、minimax-m2.5、qwen2.5-vl-72b-instruct 等模型

7. Cursor 配置

  1. 打开 Cursor Settings。
  2. 进入 Models 或 API Keys 相关页面。
  3. 找到 OpenAI API Key、OpenAI Base URL、Custom Base URL 或 Override OpenAI Base URL 一类字段。
  4. Base URL 填 https://api.xingdingwangluo.cn/v1，API Key 填 XD API 令牌。
  5. 保存后点击 Verify，或直接新建一次聊天测试。
Cursor 的不同版本字段名称会有差异，但原则一样：把 OpenAI 的 Key 和 Base URL 指向 XD API。不要把 Base URL 填成完整的 /v1/chat/completions。

8. 国产 IDE / 插件通用填法

很多国产 IDE、AI 编程插件、桌面客户端都支持“OpenAI 兼容”或“自定义模型服务”。只要看到类似字段，就按这个模板填：

字段名可能叫应该填什么
API Host / Base URL / 接口地址 / 服务地址https://api.xingdingwangluo.cn/v1
API Key / Token / 密钥你的 XD API 令牌
Provider / 接口类型OpenAI Compatible、OpenAI 或 自定义 OpenAI
Model / 模型 ID模型名，例如 deepseek-v3 或 qwen2.5-vl-72b-instruct

如果软件只支持官方账号登录，不支持自定义 Base URL，那它就不能直接接入 XD API。

9. 模型怎么选

场景新手推荐模型说明
日常代码问答deepseek-v3通用、稳定，适合先跑通。
轻量中文问答qwen2.5-7b-instruct速度快，成本低。
更强中文与代码qwen2.5-32b-instruct能力更强。
长上下文qwen2.5-14b-instruct-1m适合读长文档。
多模态图片理解qwen2.5-vl-7b-instruct轻量视觉模型。
高成本视觉/余额消耗测试qwen2.5-vl-72b-instruct已验证 default 可调用，成本较高。
向量检索bge-m3用于 embeddings，不用于普通聊天。
重排序bge-reranker-v2-m3用于 rerank，不用于普通聊天。

2026-05-16 起，已部署 CMCC token 计费模型不再用 vip/agent 做访问门槛；如果出现无可用渠道，优先检查模型名是否拼错。

10. 测试与排错

10.1 用 curl 测试聊天

curl https://api.xingdingwangluo.cn/v1/chat/completions \
  -H "Authorization: Bearer 你的_XD_API_令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-v3",
    "messages": [{"role": "user", "content": "只回复 ok"}],
    "max_tokens": 20
  }'

10.2 常见错误

现象原因处理
401 / token invalidKey 填错、复制不完整、用了旧令牌重新复制或新建令牌
403 / 无权访问分组令牌仍使用旧分组或缓存未刷新新建默认分组令牌，或重新登录后再试
Invalid URL (GET /v1)工具把 /v1 当成了可访问接口，或 Base URL 末尾又被重复拼了一次 /v1Base URL 只填 https://api.xingdingwangluo.cn/v1，不要再拼到 /v1/chat/completions
404Base URL 大概率填错，或者工具实际在请求不存在的完整路径大多数工具只填 https://api.xingdingwangluo.cn/v1
模型不存在模型名拼错或该分组不可见复制报告中的模型名，先用 deepseek-v3 测试
一直无响应网络或代理问题先用浏览器打开站点，再用 curl 测试
