XDAPI 企业客户适配建议

XDAPI / MaaS 运营文档

更新时间：2026-05-29 18:33 CST

结论

企业客户的定价和权限建议放在 XDAPI/New API 侧实现，而不是改上游 MaaS。上游移动 MaaS、天翼云 MaaS 是成本与资源供应层；XDAPI 是客户、分组、倍率、限流、渠道路由、账单展示和审计的商业分发层。

推荐做法

1. 标准客户继续使用公开 1x/3x/5x 倍率组。

2. B 端客户如果谈了独立价格，创建企业专属分组，例如 corp_acme_2026，不要复用 vip/agent/auto。

3. 企业分组可以设置独立 GroupRatio、充值/套餐、请求速率、可用渠道和可用模型范围。

4. 如果企业需要 SLA 或隔离，把“企业专属分组 + 专属渠道 + 专属上游 key/账号”组合使用；只建分组不能解决上游资源竞争。

5. 如果企业价格低于公开价，必须核算上游成本、优惠时段、批量推理和缓存命中，否则容易倒挂。

6. 如果企业要求指定供应商，例如只走天翼云或只走移动 MaaS，应在 XDAPI 渠道路由层隔离，避免同名模型跨上游混用。

典型企业方案

场景XDAPI 配置上游配置适用性
单一企业折扣价企业私有 group + 独立倍率共用现有上游 key适合轻量 ToB 试点
企业独立额度与审计企业 group + 专属 token + 月度报表可共用上游，也可专属 key适合正式合同客户
企业 SLA / 高并发企业 group + 专属渠道 + 专属上游账号/key建议独立上游资源池适合生产业务
指定供应商合规企业 group 只绑定指定供应商渠道上游按合同采购适合政企/行业客户

不建议的做法

  • 不建议把企业客户塞进公开 1x/3x/5x 后再手工解释特殊价格。
  • 不建议恢复 vip/agent/auto 作为业务分组，这会重新引入模型不可调用的问题。
  • 不建议只在上游 MaaS 改价格。XDAPI 用户余额、套餐、模型可见性和账单仍然在 XDAPI 侧，最终客户看到的是 XDAPI 规则。
  • 不建议在没有真实 POST 验证前把新上游模型公开给企业客户。

对当前 XDAPI 的落地建议

  • 保留公开 1x/3x/5x 作为零售和普通开发者入口。
  • 新增企业客户时，按客户创建私有分组，例如 ent_&lt;customer&gt;_&lt;year&gt;，并为该分组配置明确倍率、模型范围、限流和结算周期。
  • 对大客户优先使用专属 token 和专属渠道标签，便于成本核算和故障定位。
  • 业务文档必须记录：客户分组、报价口径、上游成本来源、可用模型、限流、是否共用上游 key。
