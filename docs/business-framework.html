XD API 业务框架与分组策略

本页记录当前 XD API 面向中国移动 MaaS 上游的运营框架。2026-05-18 起，业务分组改为倍率语义：1x、3x、5x；分组不再表达身份权限，也不作为模型访问门槛。

当前结论

  • 已生效 所有已部署 CMCC token 计费模型，1x/3x/5x 三个倍率组都可以通过 API 调用。
  • 已公开 前台 /api/pricing 与登录态 /api/user/models 均返回 27 个模型。
  • default、vip、agent、auto 不再作为公开业务分组或渠道路由组。
  • 高价模型仍保留在独立“高成本模型渠道”中，便于后续观测和路由维护，但不再用身份分组限制访问。
  • 2026-05-22 核对新增 qwen3.6-plus、qwen3-max、qwen3.5-plus：上游列表可见但运行时 404，暂不公开到 XDAPI。
  • 当前 3x/5x 体现更高计费倍率和更高 group-level 请求额度；若要承诺真实更快响应，还需要接入独立更快上游资源或优先级队列。

后续规则

  1. 不要再用 default/vip/agent/auto 做公开业务分组或模型可用性门槛。
  2. 新分组必须表达可解释的价格/速度差异，例如更快上游资源池、更高优先级或更高限流。
  3. 涉及业务框架、渠道、分组、价格的变更，必须同步更新本 GitHub Pages 和技能文档。
